# shadcn-admin 的实际使用与接入边界

## 可借鉴的采用场景

已有后台实践采用了本项目的页面壳与基础控件，并复用了表格工具栏、分页、表头和批量操作。这些采用说明它具有实际参考价值；业务项目中的服务端查询、加载、失败和重试状态仍需自行实现，不能当成原版自带能力。

| 场景 | 查看位置 | 接入业务时需要补齐 |
| --- | --- | --- |
| 后台导航与页面壳 | `src/components/layout/` | 导航结构、权限与路由 |
| 基础控件 | `src/components/ui/` | 字段语义、校验和业务状态 |
| 列表、筛选与分页 | `src/components/data-table/`、`src/features/tasks/` | 服务端查询、分页协议和错误处理 |
| 用户表单 | `src/features/users/` | 真实保存接口、授权和反馈 |

独立原版保留完整示例，适合比较交互和研究组件组织。正式采用时记录上游版本与许可证，业务改动留在使用方项目，避免更新原版时覆盖业务实现。

## 原版示例与真实业务的区别

- [Users 表单](../src/features/users/components/users-action-dialog.tsx) 的 `onSubmit` 调用 `form.reset()` 和 `showSubmittedData`，不保存用户到数据库。
- 仪表盘统计、任务与用户列表属于上游样例数据。截图用于展示界面，不代表业务运行结果。
- Clerk 登录与真实邀请需要独立配置和验收；本次试用未执行相关账号写操作。
- 当前手机表格需横向查看右侧列，搜索提示有截短，应结合实际字段和任务重新评估移动体验。

本次试用范围与图片见 [中文介绍](../README.zh-CN.md)，版本与更新方法见 [上游说明](../UPSTREAM.md)。正式接入时，应在业务项目完成接口校验、权限、持久化与页面状态验证。
